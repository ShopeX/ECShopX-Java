# Files

- [Bundle Anatomy and Layering Conventions](bundle-layering.md) - The internal package structure of one business Bundle (api/service/domain/mapper/integration/client/auth/gateway/dispatch/cron/port/config/repository) and the dependency-boundary rules that decide where new code goes — one domain per Maven module, Ports through ecshopx-common, assembly only in ecshopx-bootstrap — using ecshopx-orders as the worked example and cross-checked against goods, members, kaquan, digios, shuyun, and companys.
- [Cross-Bundle Ports and Wiring in Bootstrap](cross-bundle-communication.md) - The five mechanisms Bundles use to talk to each other without circular Maven dependencies — common/bundle-owned Ports (including auth, openapi, operatorcart, common.payment, common.goods.port, and digios seams), dispatch publisher interfaces in ecshopx-common (operator/POS-store-account create, withdraw job, member create-success with the new-customer tag listeners), the dispatch bus with bootstrap registration configs, Spring transactional events, and bootstrap-hosted cycle-breaking adapters — plus a decision table for choosing between them.
- [System Overview and Runtime Topology](overview.md) - The big-picture map of ECShopX-Java — the Spring Boot 3.5 / Java 17 multi-module Maven reactor under cn.shopex:ecshopx (revision 5.5.3), the single ecshopx-bootstrap Spring Boot entry that assembles 49 business Bundles, and the runtime topology (Undertow on 18080, MySQL via MyBatis-Plus, multi-DB Redis, XXL-JOB admin + executor, Redis-backed dispatch queues, and the /api, /storage, /wechatAuth URL spaces).
- [HTTP Request Lifecycle, Auth, and Response Conventions](request-lifecycle.md) - What happens to an HTTP request in the single ecshopx-bootstrap Spring application — Undertow's PHP-compatibility settings and the StorageAwareHttpFirewall, the annotation-driven auth/middleware interceptor chain (FrontAuth/FrontNoAuth/AdminAuth/FrontMerchantAuth/QywxSalespersonAuth/Activated/DataPass/ShopLog), the POS dual-JWT chain (PosJwtAuthenticationFilter, PosJwtIssuer, PosJwtBlacklist, PosJwtPathWhitelist, DualJwtSupport), the merchant-wxapp JWT servlet filter, the openapi signed-request auth interceptor with Redis replay guard, FlexibleBody binding of JSON/form/multipart plus the merged-params controller idiom, locale resolution, and the ApiResult / @DingoResponse error-envelope conventions picked by GlobalExceptionHandler.
